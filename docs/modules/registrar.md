### 5.11 Company Registrar (topbar dropdown → `regd` group)

**a) BM/AGM Minutes (`js/bmAgmMinutes.js`, `bm-` prefix)** — generates Board Meeting minutes, AGM minutes, the Companies Act §51 capital-structure report, two registrar letters, a Beneficiary Owner declaration and (conditionally) a "Change of Board of Director" set — all ten pages in one Word file, Nepali, generated as LIVE tokens rather than fill-in-the-blank text. Fills `assets/templates/bm-agm-minutes.docx` via DocumentEngine/docxtemplater (`{{token}}` delimiters, `paragraphLoop:true`).

**Rebuilt from scratch 2026-08-20** against a new source document the firm provided (superseding the original template built 2026-07). **This time the build tooling is committed** — `tools/bmAgmBuild/build.mjs` — precisely because the *old* pipeline wasn't (`docs/history/HANDOFF.md` §4 documents that gap; don't repeat it). Run `node build.mjs "<path to the firm's real source .docx>"` from `tools/bmAgmBuild/` to reproduce or extend the template; the source file itself is never committed (real client name/PAN/registration number — §1 rule 7) so the path is always external. That subfolder carries its own `package.json` (`preeti-to-unicode`, `preeti`, `jszip`) — the one deliberate exception to this repo's zero-npm-dependency rule, because a one-time Preeti→Unicode decoder is exactly the kind of thing that goes wrong hand-rolled (the old pipeline's multi-day ligature/reph-reordering debugging, same `HANDOFF.md` section). The build script's header comment explains each step; `docs/history/HANDOFF.md` §4–5 is now superseded for BM/AGM specifically (kept for the Preeti-conversion background) — this file is the current record.

**Attendee model changed with the new template**: the source numbers the chairman *and* every shareholder in one list (chairman first, role अध्यक्ष; the rest, role संचालक) — unlike the old template's unnumbered-chairman convention. `bmBuildAttendees()` builds this from the same data as before (`clients.chairman_name` + `clients.shareholder_name` + `client_shareholders`, unchanged), and tags each entry `isChairman` for the two role-conditionals in the Director's Declaration pages. **The Director's Declaration (Companies Act §92(1)) is now a real per-attendee loop**, not a fixed two-page pair — the source had one page for the chairman and a near-identical duplicate for the first shareholder; the build collapses that into one `{{#attendees}}` loop body with an explicit page break at the top of each iteration (so any attendee count gets one page each, not just two — a real bug the first pass shipped, caught by rendering a 3-attendee test case before install).

**New fields this template needs that the old one didn't**: `bm-letterDate` (the registrar letters' own date — distinct from `bm-agmDate` in the source), `bm-termYears` (director reappointment term, defaults to 4), `bm-bmExtraTitle`/`bm-bmExtraDecision` and `bm-agmExtraTitle`/`bm-agmExtraDecision` (each meeting's one case-specific agenda item + its decision — the source's "Additional Proposal" placeholder), and `bm-boardChanged` + `bm-boardChangeDate` (a checkbox gating the entire "Change of Board of Director" block — its own minutes page, a tapsil line in the second registrar letter, and the Director's Declaration loop — behind one `{{#boardChanged}}` conditional in the template, so unchecked cleanly omits all of it rather than three separate toggles that could disagree). **AGM time is fixed at ०९:०० in the template text, not a token** — confirmed with the user; the old `bm-agmTime` field and `{{agmTime}}` token are gone. **No `{{auditFee}}` token exists any more** — this source phrases the audit fee as "by mutual agreement between board and auditor" rather than stating a figure; `bm-auditFee` is gone from the form.

**`REGD_AUDIT_FIRMS` (built in `js/core/orgIdentity.js`) now also carries `address`** — added for this rebuild, since the registrar letter's बोधार्थ (cc) line needs the auditor firm's address alongside its name. Purely additive; every other consumer of that array (Auditor Change's picker) ignores the extra field.

**Capital figures in the §51 report are now live tokens** (`authorizedCapital`/`issuedCapital`/`paidUpCapital`, same `clients` columns as before) — the old template left this table as static sample text from whichever client it was originally built against, a known gap `HANDOFF.md` flagged as a build-tooling limitation, not a design choice; that limitation doesn't exist in the new pipeline. **Share count next to each capital figure ("२५,००० थान") is still static** — deliberately: the old data model never tracked share count as its own field, and this rebuild keeps the same field set rather than opening a schema change mid-rebuild.

Client search by registration number/PAN (digit-agnostic) unchanged; live docx preview, autosave draft, completion indicator, zoom, print (one page per sub-document, fitted via the existing font-scaling `bmFitPagesToSheet` — unchanged mechanism, now fitting more page shapes). **Not yet independently proofread by the firm** — the Preeti decode was validated against `org_firms` data and cross-referenced phrase-by-phrase within the document (see `build.mjs`'s CORRECTIONS import), and the rendered output was checked structurally (unzipped, every token confirmed filled, page-break count confirmed to scale with attendee count) — no Word/LibreOffice available to open it visually. The user's plan is to have their senior review a real generated document and report anything to fix.

**b) Auditor Change (`js/auditorChange.js`, `ac-` prefix — shares the prefix with Add Client, §10.2)** — two documents from one shared form: Board Resolution + registrar notification letter (`auditor-change-*.docx` templates). Same DocumentEngine architecture as BM/AGM, same UI pattern as the Report Builder (Edit/Preview, per-document preview tabs); B.S. date validation on blur; known-firm quick-fill picker (`attachFirmPicker` over `REGD_AUDIT_FIRMS`). No autosave/inline-edit yet (deliberate trim).

**c) Stubs** — Company Registration, Company Secretary Appointment (`cs-` prefix, added 2026-08-10): UI built, logic is `moduleComingSoon()` in `js/registrar.js`. Real remaining product surface. (Party Ledger used to share this stub; it became a real module on 2026-07-26 — §5.16. Share Transfer, Increase Capital and PIN Reset were removed 2026-08-10 by user decision — the firm doesn't do that work; recoverable from git history.)

**d) Company Profile (`js/companyProfile.js`, `cp-` prefix)** — added 2026-07-27 as the new home for the seven statutory fields removed from the general Add/Edit Client form (§5.7): registration number, chairman name, shareholder name, authorized/issued/paid-up capital, and VAT status. **Same `clients` columns, same data** — only the editing surface moved, because this data is Nepalese company-registration lookup material that was noise on the form for the ~150 proprietorship firms that carry none of it. A client search (digit-agnostic, by name/registration number/PAN — this screen is reached holding a registration number, not a name) loads the record into a form; a **Profile completeness meter** (reusing the `.cd-meter-*` look) tracks how many of the six non-VAT fields are filled. Saving updates `clients` directly and patches `window.clientsList` in place so BM/AGM Minutes and Auditor Change see the new values without a reload, and logs `company_profile_saved` to AuditLog.

> **Removed module — VAT Return OCR** (removed 2026-07-14 by user decision; the firm won't use it). It read scanned IRD VAT Return PDFs via digit-only OCR and filled the firm's Excel workbook. The removal took with it `js/vatReturn.js`, four engines whose only consumer it was (`ocrEngine`, `pdfEngine`, `visionEngine`, `validationEngine`), `DocumentEngine.workbookToBlob`, the `pdfjs-dist`/`tesseract.js`/`exceljs` CDN tags, and `assets/templates/vat-detail.xlsx`. (`exceljs` was re-added shortly after for the Depreciation module — §5.8 — but the four engines and the OCR/PDF CDN libraries stay gone.) All of it is recoverable from git history (last commit containing it: `ad0e9f2`); its engineering record lives in `HANDOFF_VAT.md` / `HANDOFF_2026-07-05.md`. Historical `audit_log` rows with `module: 'vatReturn'` remain valid; `vat_filings.status` keeps `ocr_processing` as a manual status.
